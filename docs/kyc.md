# KYC (Identity Verification)

## Current behavior

Frontend-only integration against the Glass backend KYC API (`kyc-frontend-integration.md` is the contract source). Smile ID Biometric KYC is the provider; the frontend initiates a challenge with `{ idType, callbackUrl }` on `POST /kyc/attempts` — `callbackUrl` defaults to the Smile ID result webhook (`https://api.glasspay.app/api/v1/webhooks/smile-id`, the backend team's callback) and is start-attempt only; Glass then mints the capture token with it embedded. The browser never stores the token (memory only) and never sends ID numbers or selfies to Glass.

- **Wizard modal (primary surface):** `src/components/kyc/KycWizardModal.jsx` runs a 4-step flow (Overview/payoff → ID type → Capture prep → Status) with a pill stepper, the flat 2-color illustration system (`components/kyc/illustrations.jsx`), a viewfinder-style capture-prep screen, and a live status narrative. It mounts `useKycFlow` (`components/kyc/useKycFlow.jsx`), which owns step state, smart initial step (derived from `GET /kyc` status), the Smile-ID error bounce-back, and bounded status polling. The capture-prep screen is Glass-built only — actual capture still happens inside Smile ID's hosted window.
- **Gates/badges open the wizard:** community create/manage (`useKycGate`) opens `KycWizardModal` directly (the old `KycRequiredSheet` interstitial is gone — no modal-on-modal), as do the KYC status badges on Communities Home, member Home, My Communities, and the Settings row. `historyPath` wires the footer's history link per shell.
- **Member:** `/member/verify-identity` reads `GET /kyc` as the source of truth, starts/refreshes an attempt, runs the Smile ID CDN SDK, then `confirm-submission` only on client success. Attempt history: `/member/verify-identity/history`. Both routes stay behind the member app's mobile-only device gate.
- **Dashboard (desktop):** `/dashboard/verify-identity` (+ `verify-identity/history`) is the dashboard-styled counterpart — a deep-linkable shell (direct URLs, the getting-started checklist, History) around the same flow. Interactive entry points (badges, gates, the Settings row) open the wizard modal inline instead of routing here.
- **One shared flow:** member page, dashboard page, and wizard modal are thin chrome around `useKycFlow`; the Smile ID state machine is `src/hooks/useKycVerification.js`. Pages render the stepper/steps/footer inline; the modal does it inside `GlassModal` (portal, focus trap, fixed footer).
- **Status refresh:** on window focus and after mutations everywhere; while the flow is parked on a non-terminal status it additionally refetches every 6s, bounded at ~2 minutes (`MAX_POLLS` in `useKycFlow`), then settles into a "we'll notify you" card. The live narrative ("Uploading… → Checking document quality… → Verifying with issuer…") cycles only while status is in flight (`isKycInFlight`).
- **Status interpretation** lives in `src/utils/kycStatus.js` (labels, chips + pill dot colors, `isKycApproved` / `isKycTerminal` / `isKycInFlight`, id-type labels). Admin table colors also mirror the enum set in platform-admin `shared.js` `STATUS_COLORS`.
- **Gates:** community create/manage shows the wizard only when summary is explicitly not `APPROVED`. While the summary is still loading the trigger holds (disabled/spinner) — "still loading" never means "let them through". A failed summary fails open so a broken endpoint can't lock admins out; backend remains authoritative (`docs/authorization.md`). Platform staff are exempt per the backend contract (they can't start a personal attempt). On approval, the wizard's Done resumes the interrupted action — the gate remembers the continuation (create flow step, community card) instead of returning to the dashboard. The wizard re-submits a create the backend rejected with the KYC 403 (`"Approved KYC is required for community staff participation"` — stale client summary or a deep link past the gate); dismissing it drops the held submission and leaves the form intact.
- **Badges:** Settings Account row, Home header (when not approved), Create Community actions.
- **Platform admin:** Admin Panel → KYC tab lists `/admin/kyc/attempts` (default `IN_REVIEW`), detail modal loads full evidence before Approve/Reject/Revoke/Attempt-policy (reason required; `409` reloads).
- **Kill switch:** `VITE_FLAGS={"kycDisabled":true}` hides member entry points and gates.
